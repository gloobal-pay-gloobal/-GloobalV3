# Restructure Gloobal Project into Front-End / Back-End Organization

## Background

The entire Gloobal application currently lives in a single **781KB monolithic JSX file** ([GloobalApp.jsx](file:///d:/gloobal-new version/GloobalApp.jsx)) containing ~15,339 lines. This file was generated by inlining an entire modular codebase — every module is labeled with `// src/...` origin comments showing where it originally came from. The project needs to be split back into a well-organized, maintainable folder structure.

### Current State
```
gloobal-new version/
├── GloobalApp.jsx                     # 781KB monolith (15,339 lines — ALL code)
├── FIXES.md                           # Bug-fix documentation
├── gloobal-essentials-preview/        # Vite + React preview project (uses GloobalApp.jsx)
│   ├── index.html, package.json, vite.config.js
│   ├── src/GloobalApp.jsx, src/main.jsx
│   └── dist/                          # Production build output
└── financial-principles-tests/        # Node.js test suite (166 tests)
    ├── app_bundle_testonly.mjs         # Generated test bundle
    ├── scripts/build-test-bundle.mjs
    ├── src/data/essentialsBaseline.js
    └── tests/ (10 test files)
```

## User Review Required

> [!IMPORTANT]
> **This is a code-splitting operation, not a rewrite.** Every module extracted will contain the exact same code from `GloobalApp.jsx`. No logic will be changed — only `import`/`export` statements will be added to connect the modules. The monolithic file will be replaced by ~70+ individual files.

> [!WARNING]
> **The existing test suite and preview app must keep working after restructuring.** The `financial-principles-tests/` test bundle regeneration script (`build-test-bundle.mjs`) currently parses `GloobalApp.jsx` by its `// src/...` comments. After restructuring, the tests will import directly from the actual source modules instead, which is better. However, the transition will require updating the test bundle script or test imports.

## Open Questions

   - (A) Update the test imports to point directly at the new modular source files (cleaner), or
   - (B) Keep the existing bundle-generation approach and update the script to scan the new folder structure?

## Proposed Changes

The new structure splits the codebase into **back-end** (domain logic, services, data) and **front-end** (React components, screens, UI utilities), with shared infrastructure at the top level.

### Back-end Layer — Domain Logic Extraction

Every `// src/domain/...`, `// src/data/...`, `// src/utils/...`, `// src/core/...`, and `// src/services/...` section from the monolith will be extracted to its own file under `backend/`. Each file will:

- Contain the exact code from its section in `GloobalApp.jsx`
- Add proper `import` statements for cross-module dependencies
- Add `export` statements for classes/functions consumed by other modules

**~50 files created** covering: domain entities, services, stores, data files, and utilities.

---

### Front-end Layer — React Components Extraction

Every `// src/components/...`, `// src/screens/...`, `// src/features/...`, `// src/hooks/...`, `// src/adapters/...`, and `// src/constants/...` section will be extracted under `frontend/`. Each file will:

- Import React and domain dependencies from `backend/`
- Import UI dependencies from sibling `frontend/` modules
- Export components/hooks for consumption

**~30 JSX/JS files created** covering: components, screens, features, hooks, adapters.
